# 장바구니 FE 미션 리뷰어 가이드

# 1단계

[리뷰 포인트]

1. 상태 설계가 SSOT 원칙에 따라 설계되어 있는가?

- 핵심 상태(상품 정보, 수량, 선택 여부, 쿠폰)가 단일 원천으로 관리되는가? 동일한 데이터가 여러 곳에 중복 저장되진 않는가?
- 장바구니 선택 상태를 localStorage에 저장하여 새로고침 후에도 유지하는가?

2. 비동기 요청 상태를 사용자에게 적절히 노출하는가?

- API 요청 중 로딩 UI(스피너, 스켈레톤 등)를 표시하는가?
- API 에러 발생 시 사용자에게 에러 메시지를 보여주는가?
- 비동기 상태(loading / error / data)를 하나의 커스텀 훅으로 캡슐화하였는가?

3. 컴포넌트 인터페이스가 사용하기 좋게 설계되었는가?

- Props 이름이 세부 구현을 드러내지 않는가?
- 컴포넌트의 다양한 use case를 고려했을 때 인터페이스가 자연스러운가?

4. 테스트가 주요 기능을 의미 있게 검증하는가?

- 주요 기능(선택/해제에 따른 결제 금액 변동, 수량 변경, 상품 제거 등)을 스스로 정의하고 테스트하는가?
- RTL로 사용자 관점(클릭, 입력, 화면 변화)에서 테스트를 작성하는가? 내부 구현이 아닌 동작을 검증하는가?

5. 코드 퀄리티를 준수했는가?

- 컴포넌트는 UI 표현에 집중하고, 비즈니스 로직은 커스텀 훅 또는 도메인 함수로 분리했는가?
- 한 컴포넌트/훅이 하나의 역할만 담당하는가?
